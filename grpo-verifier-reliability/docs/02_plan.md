# 02｜任务框架与验收门槛

本计划与 [全仓库产出与存储准则](../../docs/EXPERIMENT_ARTIFACTS.md) 配合使用；新运行使用其中的清单与记录模板，小型 CPU 检查按轻量要求记录。

## 阶段 A：看懂并验证基础（不租 GPU）

- [ ] 手算 rewards=[0,1,0,1] 的均值、总体标准差和优势。
- [ ] 解释正优势 ratio>1.2、负优势 ratio<0.8 时为何梯度变零。
- [ ] 运行全部 CPU 测试与三种 toy 条件。
- [ ] 审计冻结候选上的 FP/FN，确认不是混用了训练判分器和评测判分器。
- [ ] 说明 toy 的限制：策略直接选择正确/偏移候选，不能衡量真实算术推理。

## 阶段 B：真实模型的正确性与费用冒烟

- [ ] 固定代码 commit、依赖、模型版本、任务种子与解码设置。
- [ ] 在训练前单独评测模型；若准确率饱和或全零，先调整任务/提示，再冻结设置。
- [ ] 手查至少20条输出，区分格式错误、计算错误和 verifier 错误。
- [ ] 先 clean 模式20步，保存逐样本 reward、独立评测和 checkpoint。
- [ ] 测 token/s、GPU 峰值、实际租用时长；根据账单而非模型大小估算费用。
- [ ] 从 checkpoint 恢复，验证步数与模型可加载；不要未经验证声称位级可重复。
- [ ] 测量 checkpoint/原始记录大小与保存开销，确认空间余量、回传目标和实例期限。
- [ ] 核查采样组、更新步与 attempt/event 的关联；在无卡阶段回传至少一个封口证据分片并读回校验，不要求先上传完整权重。

**停止条件**：奖励和手工判分矛盾；全部组内优势为零；格式/截断主导结果；恢复损坏；费用达到事先批准的上限。
现有脚本不会监控云平台账单或自动关机。执行者须在已有授权范围内准备并验证实际停止路径；本计划不新增支出授权。未具备持久监控与停机能力前，只执行有人观察的限时冒烟。

## 阶段 C：最小对照

先在同一冻结模型输出上比较 clean/random_fp/structured_fp，保存真实 FP/FN 和子群分布。
再决定值得训练的条件，不急于跑全矩阵。

正式比较时：
- 固定训练/调参/最终测试边界、模型、优化器、解码与奖励解析器。
- 报告训练 token 与总成本；相同步数不代表相同计算量。
- 在训练样本上同时记录 noisy 和 clean reward，独立测试只使用 clean verifier。
- 至少3个训练种子；报告各次结果而不只给最好一次。
- 记录正确率、格式有效率、长度与截断、FP/FN、全同奖励组比例、训练奖励与真实分数的差距。
- 保存全部条件的原始输出和失败记录，恢复重放单独标识并按预定规则去重；需要比较训练过程时，提前指定独立保护的研究节点。
- 阶段复盘后决定最终权重是否还有补测/续训用途，不默认长期保存全部 checkpoint；原始结果和保留决定持续可追溯。

第一版整数任务仅 train/test 两个不相交池。若开始调超参，**必须另建 validation 池**，不能反复用最终 test 选方案。

## 阶段 D：从适配走向复现

逐项恢复原论文任务、模型、算法、噪声模式和统计口径；在 `experiment_record.md` 中列清变化。
若只复现现象，标题写“简化现象复现”；若原设置受预算限制，保留未完成项，不凑结论。
