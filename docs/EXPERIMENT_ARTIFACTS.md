# Reproduction 任务产出与存储准则

版本：1.0。制定日期：2026-11-02。适用于本仓库的训练、推理评测、环境适配、性能测量与存储测试。

目标是让一次有成本的执行支持尽可能多的后续分析，同时控制采集开销、存储费和维护成本。**优先保存难以重建的证据；检查点先留在实例；长期权重归档按研究价值决定。** 不以购买网盘、建设对象存储、接入仪表盘或保存全部中间权重作为开跑前提。

这是执行准则，不是自动化系统。模板中的回传、监控、停机和清理字段是计划与验收记录；填入数值不会产生定时任务。现有能力边界见第 11 节。

实现这些要求时同时遵循 [全仓库代码要求](../AGENTS.md)：**不必要的地方一定避免冗余设计和边缘保护**。按本次实验的实际需要实现采集、保存和校验，不因这份准则列出多种任务就建设通用平台或堆叠兜底分支。代码结构与注释应便于用户理解、学习和修改。

## 1. 按任务规模安排工作

| 任务级别 | 开始前最小准备 | 结束时最小产出 |
| --- | --- | --- |
| 可快速重跑的 CPU 检查、离线估算 | 命令、输入/版本、预期检查项 | 结果与退出状态；用于报告的数值保留输入和重算入口 |
| 依赖安装、真实硬件冒烟、存储测试 | 唯一 run ID、配置、环境、资源与时间上限、输出目录、必要采集 | 原始输出、错误、实测耗时、校验结果和未测项；训练冒烟包含保存/恢复验证 |
| 正式训练、批量评测、跨条件比较 | 完整运行清单；冻结任务与采样设置；数据切分；采集、回传、磁盘和费用计划 | 可追溯的逐样本证据、汇总与图表、资源费用、失败记录、产物清单和保留决定 |

小型检查可在一份记录中包含以上信息，不强制建立全部目录。已有项目文件可保留原名，由清单映射；不为了统一格式重跑已经完成的实验。旧实验缺失的证据必须如实标注，不补造历史数据。

## 2. 实验身份、配置和结果边界

每个新实验使用唯一 `run_id`，推荐 `<UTC时间>-<项目>-<条件>-s<seed>-<短后缀>`。同一实验恢复时沿用 run ID，增加 `attempt_id`；改模型、数据切分、奖励规则或关键超参数时创建新 run，并记录父 run。改变总目标步数的延长训练也应记录为新配置/派生 run，不能冒充严格中断恢复。

启动前保存不可变的配置快照，后续状态写入追加事件或独立状态文件。至少能追溯：

- 假设、基线、成功标准、停止条件、与原论文的差异，以及本次属于估算、教学适配、现象复现还是原设置复现。
- 代码 commit；有未提交代码时保存实际使用的补丁和新增文件快照/哈希。commit 本身不足以描述脏工作区。提交证据前检查快照中的凭据和本地路径。
- 模型来源和固定 revision，配置、tokenizer/processor、权重索引与文件哈希；adapter 必须关联确切基础模型。模型存一份共享缓存，不为每个 run 重复复制。
- 数据集/任务/环境版本、样本清单或可确定重建的生成规则、切分与种子；提示模板、解析器、verifier 和解码参数。训练、调参验证、最终测试用途分开。
- 实际命令、有效配置（包括重要默认值）、依赖锁定结果、容器镜像 digest（若使用）、Python/框架/CUDA/驱动、硬件与分布式布局。
- 启止 UTC 时间、实例/任务标识、计费模式、允许费用上限、预计产物大小、实际挂载路径和回收期限。凭据、Cookie、授权码和带令牌的下载链接不进入这些文件。

`completed` 仅表示执行完成；证据是否齐全、是否存在实例外副本、是否需要补测分别记录。缺失值使用 `null` 并说明原因；未采集、不可用、不适用和真实的 0 必须区分。

## 3. 必须优先采集的证据

### 通用要求

正式实验默认保存全部实际模型输出及逐样本结果，失败与超时也纳入记录。输出是后端实际返回的内容，不推测未提供的内部状态。每条记录至少关联 run、attempt、样本/任务 ID、事件 ID、时间和状态；训练再记录 update/microstep、采样组和生成序号，交互评测再记录 trial、episode、step。

输入可使用“冻结任务快照 + 稳定 ID + 哈希”引用，避免反复复制。恢复重放和重试另设 attempt/event ID，保留原始记录，并在派生统计中明确去重及最终采用哪个结果。不能用一组重试中的最佳答案替代事先定义的统计规则。记录预期、成功、失败、取消、未完成和缺失样本数。

| 场景 | 优先保存的原始证据 | 直接支持的分析 |
| --- | --- | --- |
| 推理/基准评测 | prompt 或冻结输入引用、完整回答、解析结果、逐题评分及依据、输出 token 数、解码设置、延迟、截断/停止原因 | 错误归因、重新判分、子群表现、吞吐与长度分布 |
| GRPO/训练 | 采样组与输出、干净/训练奖励、FP/FN 判定依据、长度/截断、实际组内统计及优势；更新步 loss、学习率、梯度范数、累计训练/生成 token | 奖励投机、零优势组、训练稳定性、相同 token/成本下的对照 |
| GUI/Agent 任务 | 每次供模型观察的截图/观测、实际上下文构造规则、原始输出、解析动作、工具调用与返回、环境状态/版本、verifier 结果、终止原因 | 成败轨迹、动作解析错误、环境故障、上下文与截图处理问题 |
| 环境/性能/传输测试 | 命令与版本、输入大小与哈希、完整退出状态和错误、阶段耗时、重试/中断方式、实际执行地点和账号权益 | 校验数据完整性、定位限制、比较环境或配置变更 |

token ID、attention/loss mask、实际训练 logprob 等按研究问题提前确定：涉及 token 损失、解析或截断归因时必须保存足够数据；短回答实验优先全量记录。KL、熵、clip fraction 等记录框架实际定义与聚合方式；拿不到时标缺失，不能将近似量写成真值，也不能默认它们已被现有 TRL 入口采集。

对截图保留模型实际使用的原始观测、必要处理参数及坐标映射；缩略图仅用于浏览，不能替代研究所需原图。重复观测可按哈希共享。视频、环境快照、全量 logits、每层激活和完整梯度张量不默认全存：有具体问题时再限定窗口、频率和样本。

保存输出后可以重判已有回答、改图表；换 prompt、换策略、生成新答案或与新环境交互仍需要模型及新的执行。不要将“原始日志齐全”解释为可以回答所有未来问题。

### 资源与费用

默认每次优化器更新记录训练标量，每个评测任务/episode 记录结果，硬件指标以 10 秒为初始采样间隔；短任务应另用框架峰值或事件采样，不能用 10 秒间隔宣称捕获瞬时峰值。正式运行前用冒烟校准采集频率与额外耗时。

记录每卡显存、GPU 利用率、CPU/RAM、磁盘剩余空间和增长、有效吞吐、OOM/超时，以及加载、生成、更新、评测、保存和传输的耗时。PyTorch allocated/reserved 和设备总占用分别记录；并行阶段不能简单相加当总墙钟时间。

费用分 GPU、无卡/CPU、磁盘/共享存储、流量、外部 API 等项；同时记录估算与账单实付口径。按相同步数比较时还要报告 token、样本和实际费用。不因切成无卡模式就把后续费用记为零。

## 4. 分析与图表应由原始证据重建

每次正式实验交付一份简洁报告，包含设置、结论、反例、失败与局限、证据入口和下一步最便宜的验证。根据问题选择图表，不要求生成与任务无关的全套图。

| 任务 | 默认分析 |
| --- | --- |
| 基准评测 | 总体及子群成绩、逐 trial 结果、失败类型、长度/延迟分布、成功率与步数/token/成本关系 |
| GRPO | 训练奖励与干净评测、二者差距、FP/FN、格式/截断、全同奖励组比例、长度分布、稳定性、多 seed 结果 |
| 性能/存储 | 端到端耗时、传输字节/样本量、有效吞吐、资源曲线、重试与完整性校验 |

图旁明确数据分母、单位、缺失处理、平滑、聚合粒度及区间方法；相关样本不能冒充独立种子。FP/FN 的计数和对应条件分母一起保存。中途成绩标明完成进度，最终按基准定义处理失败、超时和未完成，不静默剔除困难样本。

保存绘图脚本、参数、输入文件哈希/清单、图表数据表和输出图。长期保留底层证据；派生表和图片可以重建。正式报告按实际需要输出 PNG/SVG/PDF；交互页面可选，不能成为唯一证据入口。TensorBoard、W&B、MLflow 等可选，必须能导出独立于服务的原始记录。

## 5. 文件布局、格式与产物清单

推荐工作目录，未涉及的部分可省略：

```text
<project>/runs/<run_id>/          # 实例上的工作区，默认不进 Git
  run-manifest.json              # 启动配置与采集/保留计划
  status.json                   # 当前状态、未完成项、下次处置期限
  attempts/<attempt_id>/         # 命令、环境变更、stdout/stderr、事件
  raw/                          # 逐样本/逐步记录及观测
  metrics/                      # 标量、系统监控和费用记录
  checkpoints/                  # 滚动恢复点
  milestones/                   # 独立保护的研究节点
  final/                        # 最终推理权重或 adapter
  analysis/                     # 派生数据、图表与分析参数
  artifact-manifest.json         # 产物索引、校验与副本状态

<project>/experiments/<run_id>/  # 经检查后进入 Git 的精简证据包
  record.md
  run-manifest.json              # 脱敏后的有效配置/来源
  artifact-manifest.json
  summary.json
  figures/                      # 精选图表及其数据/脚本入口
```

逐事件数据用 UTF-8 JSONL，适合追加和故障恢复；封口分片用 gzip/zstd 压缩，按 run/attempt/任务或时间分片，避免单个巨型压缩包。大量结构化分析数据可另转 Parquet；先校验转换前后行数与字段，再决定是否清理可重建的重复格式。记录 schema 版本、单位和压缩格式。

使用流式写出，按样本/episode 结束刷新；只传输已封口分片，记录最后持久化的位置。检查点先写临时目录，框架保存完成、文件齐全后才标记可恢复；后台任务不能上传仍在写入的 checkpoint。临时目录改名不等于所有分布式分片都已完整，需核对实际框架的完成条件。

每个要保留的产物登记：角色、run/attempt/step、文件路径、字节数、SHA-256、依赖（基础模型/tokenizer/数据/脚本）、保留类别、各副本位置与校验时间。目录使用逐文件清单；多段归档记录顺序和重组方式。校验凭据不能是会过期的签名链接；保存稳定存储标识，授权另行管理。

复制状态建议使用 `planned / local_only / copying / verified / failed / missing / deleted`。上传命令成功、能列出文件、返回相同文件名都不足以证明可恢复：核对大小和内容哈希；后端校验不可验证时下载读回。抽检要注明范围，不能标全量 verified。选择权重长期归档前，再验证至少一次实际加载；训练恢复还需检查完整状态与目标步数。

模板：[运行清单](templates/run-manifest.example.json)、[产物清单](templates/artifact-manifest.example.json)、[实验记录](templates/experiment-record.md)。它们是示例，不是程序已实施的 JSON Schema。

## 6. 存储分工

| 位置 | 默认内容 | 使用边界 |
| --- | --- | --- |
| Git / GitHub | 代码、配置、报告、环境清单、产物索引、小型原始证据、精选图表 | 高频日志、大数据和权重不放普通 Git；本地提交不代表远端已同步 |
| GPU 实例磁盘 | 基础模型缓存、正在生成的原始数据、滚动 checkpoint、待评测最终模型 | 当前工作存储，允许暂时作为权重唯一副本；必须登记回收/到期风险和下次处置时间 |
| 当前控制机器或其他已存在的持久磁盘 | 增量回传的完整原始数据、分析副本、必要权重 | 确认真实持久性、容量和备份责任；`/tmp` 仅供临时测试，不是长期归档 |
| 对象存储、独立数据盘、CFS、个人网盘 | 本机容量不足、跨实例使用或选定的长期产物 | 按实际容量/传输需要启用，不预先购买；独立资源仍有自己的费用与回收期限 |
| 模型托管平台 | 选定的最终模型、需要共享的 adapter | 发布范围与授权另行决定；不把发布平台当无限免费恢复盘 |

普通 Git 建议单文件控制在 10 MiB 以内、每个 run 的精简证据包控制在 50 MiB 以内；这些是本仓库的软预算，不是平台上限。超出时先压缩、分离大原始数据并保留索引，必要的例外写明理由，不为凑体积删掉关键证据。截图/JSONL 即使不是权重，也可能不适合进入 Git。

**文件上传、下载、批量压缩和离线作图在无卡/CPU 环境执行。** 训练期间完成必要采集、轻量监控和本地分片封口；阶段性保存并停止 GPU 进程后，转无卡执行增量回传，切换后核对文件仍在且可访问。不为了上传权重延长 GPU 占用。

原始证据默认每个完成的任务批次安排一次无卡回传；长任务以 15 分钟作为本地分片与持久化窗口的规划起点。回传周期另按切换开销、带宽、任务成本与实例故障风险确定，写明形成实例外副本前的真实可接受丢失窗口；本地每 15 分钟落盘不等于每 15 分钟已备份。持续高产量时预估积压并配置足够快的目标盘/CPU 传输端，不能只设置间隔而忽略传输赶不上生成。

回传失败时保留源数据并记录错误、重试和积压大小。达到磁盘或费用停止条件时停止新增计算；在保留磁盘的前提下停卡/转无卡处理。不要等所有大文件传完才停止计费，也不要为了关机直接删除唯一证据。

## 7. 检查点与保留周期

| 类别 | 默认保留方式 | 何时可以结束保留 |
| --- | --- | --- |
| 基础模型缓存 | 实例共享一份，固定 revision 与配置/哈希 | 可重新取得且无正在使用的任务时可清缓存；重要但来源不稳定的版本单独决定是否存快照 |
| 滚动恢复 checkpoint | 实例上最近两个完整、可识别的版本 | 新版本完整保存后轮换；最早应在冒烟中验证一次实际恢复 |
| 研究里程碑 | 按事先指定的步数/token/现象单独标记 `pinned`，不受滚动清理影响 | 对应分析、补测或分支训练完成后作明确处置决定 |
| 冒烟实验最终权重 | 留到保存、恢复与评测验证完成 | 通常无需长期归档；记录验证结果和不保留原因 |
| 正式实验最终权重 | 留到冻结评测、阶段复盘及已计划补测完成 | 无新任务用途时可以不归档；有后续用途或重训代价高时选定归档 |
| 完整原始证据与运行配置 | 在项目研究/结论使用期间持续保留，及时形成实例外副本 | 不因普通磁盘轮换删除；若确需缩减，记录范围、理由及对结论的影响 |
| 可重建的图、派生表和缓存 | 按便利性保留 | 输入、脚本和版本仍在时可重新生成；报告使用的图表版本保留 |

检查点频率先根据“最多愿意损失多少训练时间”决定，再用冒烟测保存耗时调整；不要把每 10 步机械套用到所有模型。正式长任务可先以 10–30 分钟可恢复窗口作为规划起点，实际配置在 run 中写明。需要观察学习过程时另存稀疏研究节点，不能依赖最后两个恢复点还原整条训练曲线。

`final/` 的推理权重不等于完整恢复点。续训可能还需优化器、scheduler、随机状态、sampler/数据进度、训练步数、混合精度和框架状态，按实际框架核对。LoRA adapter 也需要基础模型依赖；不能为了省存储擅自改变实验算法。

“长期保留”不默认为每个 seed 的每个 checkpoint 永久保存，也不意味着只留表现最好的 seed。选定哪些 run/节点保留应基于研究用途，所有 seed 的原始结果与不保留决定都要可追溯。

阶段复盘时写明 `retain / archive / discard_after_validation`、原因、未完成用途和下次检查日期。日期到期只触发复查，不自动删除；平台更早的回收期限优先。跨实例迁移、长期暂停或释放实例时，再确定是否有必须迁出的权重，不提前建设用不到的归档系统。

## 8. 空间、费用与实例生命周期

开始前分别预算共享模型缓存、数据、原始轨迹、两个恢复点、里程碑、final、保存临时副本、分析和压缩中间文件。全参数 optimizer 状态可显著大于推理权重，不能用“模型参数字节数 × 2”估算所有检查点。

建议磁盘工作余量至少覆盖“一次新完整 checkpoint 的写入 + 下一回传窗口的原始数据”；长期任务再增加余量。记录具体字节阈值及处置动作，不能仅写“空间不足时处理”。无法保证下一次保存时，先停止新增任务、保留现场，按已声明的缓存/滚动策略释放空间；不要现场随机删大文件。

费用上限必须来自已有授权，包含无卡、磁盘、流量和收尾操作。需要停卡时为保存/切换预留时间；预算不足不能靠无限等待上传解决。任务进程停止并不代表云资源已停止计费，最终查询实例状态与计费项。

无人值守任务在启动前要有独立于聊天连接的持久任务、监控与超时/停机路径，并记录执行责任和验证结果。未实现这些能力时采用有人观察的限时冒烟，不宣称可无人值守长期运行。文档中的 `stop_conditions` 不会自行关机。

### CompShare 当前核验规则

以下仅为 **2026-11-01** 查阅结果，不是永远有效的配置；每次租用、长时间关机、重装或释放前按实际实例类型、地域和计费方式复核：

- 按量实例正常关机与删除不同。当前官方规则说明：无欠费的按量实例连续关机 7 天会回收实例、系统盘与 EIP；挂载的数据盘执行卸载，另走数据盘的回收规则。欠费、到期和抢占式实例另有规则，不能一律认为有 7 天。[回收规则](https://www.compshare.cn/docs/operation/charge/recycle)
- 删除实例会清除系统盘；删除 API 默认保留数据盘，但可通过参数同时删除。必须核对实际磁盘和参数，不把“停止”“释放”“释放数据盘”混用。[删除实例 API](https://compshare.cn/docs/gpus/instance/terminatecompshareinstance)
- 无卡模式仍有基础计算费用；按量实例关机后的扩容磁盘、数据盘、镜像等仍可能收费。包周期实例关机不意味着停止计费。[官方 FAQ](https://www.compshare.cn/docs/operation/gpufaq)

在 `status.json` 或运行记录中填写实际停止时间、资源类型、回收依据、预计期限、下次检查时间和负责执行者；检查时间应早于最早可能回收期限，留出迁移余量。不能只依赖聊天记忆或在本机写一个永不执行的定时计划。长期暂停时选择迁出或明确付费保留，避免靠反复开关机作为默认归档方式。

## 9. 四个验收节点

### 开始前

- 问题、基线、设置与数据边界冻结；输出目录唯一，不覆盖旧 run。
- 必需记录字段已有真实采集路径；尚缺字段已写入冒烟补齐计划或本次结论边界。影响核心结论的缺失必须先补齐。
- 输出目录可写，空间预算足够；明确原始证据回传目标、频率、校验方法与实例保留期限。
- 有费用/时长上限和实际可执行的停止路径；授权范围足够覆盖本次工作。

### 冒烟后、扩大实验前

- 检查真实样本、schema、采样组/episode 关联、长度与截断、奖励/评测口径。
- 验证至少一个封口证据分片回传并读回校验；不要求先上传完整模型。
- 训练执行一次保存与恢复；只按实测报告可加载、步数连续或结果一致性，分别说明，不承诺位级可重复。
- 用实测吞吐、磁盘增长、保存与采集开销修正容量、频率和费用计划。

### 一次运行结束

- 保存退出状态、错误和未完成项；核对预计样本数、去重、成功/失败/取消的分母。
- 完成原始证据清单、必要校验、汇总和可重建图表；明确实例外副本的实际位置。
- 最终权重尚需评测时继续保留；完成阶段复盘后作保留决定。任何未完成项都不能写成“全部验收”。
- 停止不再需要的 GPU 资源并核对平台状态；需要 CPU 分析/传输则按计划转无卡。记录仍计费的存储与下次处置期限。

### 删除实例、重装或释放磁盘前

- 列出会受影响的真实挂载点、关联 run、唯一副本和未完成评测。
- 必需的原始证据已有经校验的实例外副本；需要保留的权重已迁出并验证依赖、加载/恢复。
- 不保留的权重已有理由与阶段验收记录；缓存/临时文件与唯一原始证据没有混淆。
- 检查数据盘是否保留、是否仍被其他任务使用，以及后续费用与期限。遵守会话中已有操作授权；范围不明才补问。
- 操作后复核实例/存储状态，更新清单位置与 `deleted` 状态。删除本地副本不等于删除远端副本，反之亦然。

## 10. 存储服务实测不能被宣传参数代替

选用存储时核对容量、单文件上限、上传与下载权限、账号等级、API/客户端差异、地域网络、请求/流量计费，以及删除和续费机制。先用新的随机文件验证上传、下载、哈希、中断恢复，再测试实际尺寸；秒传不计为真实上传吞吐。

本仓库 [2026-11-01 夸克 CLI 测试](../storage-tests/quark/2026-11-01/report.json) 记录了普通账号下 1 MiB/8 MiB 往返哈希一致、64 MiB 可上传但 CLI 下载返回 50 MiB 上限；恢复命令可完成任务，但未证明字节级续传效率。这是特定账号/客户端/主机的实测，不推断所有网盘入口或付费账号。暂不把夸克作为大权重的必要归档环节，也不因此阻塞 GPU 实验。

## 11. 当前项目的具体落点与能力差距

| 项目 | 产出重点 | 权重策略 | 当前尚未实现/验证 |
| --- | --- | --- | --- |
| MAI-Gym | 任务/trial/step 轨迹、模型观察的截图、原始输出与动作、verifier、资源与失败类型 | 只做已有模型评测，不产生训练 checkpoint；基础模型作为可重建缓存 | 现有工作是显存评估和证据整理，正式评测采集、回传与续跑还需接入 |
| GRPO | 逐样本双奖励、采样组、优势/更新统计、独立评测、多 seed、成本 | 现有入口每 10 步保存、最多两个 checkpoint，并导出 final；先留实例；冒烟完成后一般无需长期保留权重 | 已有 reward trace/config/pip freeze，但缺统一事件标识、完整监控/来源指纹、自动回传、保护里程碑与清理验收；GPU 恢复未验证 |
| 存储/环境测试 | 输入哈希、权限/环境、命令结果、耗时、中断与限制 | 不涉及训练权重；测试原始记录归入小型证据 | 临时随机文件不作长期归档；测试工具不是全仓库备份系统 |

这些要求应用于下一次相关任务的准备和验收。先补会影响本次问题和证据保全的缺口，不要求一次性重构整个仓库。实施自动采集、监控、回传或清理时，应将验证结果写入对应项目，不能仅更新本准则就把能力标为已完成。
